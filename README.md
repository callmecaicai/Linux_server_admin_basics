## 这是什么

一台多用户、多块盘的 Linux 服务器，好几个人一起用。本合集回答：**多个人怎么共享而不互相踩踏？磁盘怎么规划分工？谁能动谁的东西（权限）？整台机器的目录按什么逻辑摆？出了报错怎么 5 分钟定位？**

- **6 章原理笔记**（`00`–`05`）：从"机器怎么认人"一路讲到"多盘冗余规划"，每章自包含、结构统一。
- **1 份排查指南**（`Linux排查指南.md`）：把原理变成"Permission denied / 磁盘满 / 加组没生效"的确定性诊断流程 + 速查卡。

> 全库示例中的用户名 / 路径 / 主机名（`alice`、`/data`、`gpu-server` 等）**均为占位，非任何真实环境**。

## 一致性脊柱

**一根主轴**：服务器管理 = 管**人** + 管**地** + 管**人对地的权利**。三者全交汇在 `ls -l` 的一行里：

```
-rw-r--r--  2  alice  ml  4096  model.pt
└─权利rwx─┘ │  └人┘  └组┘        └─地(文件)─┘
         硬链接数
```

**三个追问**（看任何权限问题都问这三句）：
1. **谁**？（哪个 user / 属于哪些 group——精确说是"哪个 UID 的进程"）
2. **什么权利**？（rwx 的哪几位、对 owner/group/other 哪一档，命中即停不退档）
3. **在哪块地**？（哪个目录 / 哪块盘，是系统地盘还是数据地盘，路径每级有 x 吗）

## 这次相比初版深化了什么

为让笔记"够深、够系统、够准"，本轮做了如下增补与纠错：

- **纠错**：`/usr` 词源是 **"user"**，不是后人编的 "Unix System Resources"（第 03 章）。
- **补进程视角**：权限检查的真正主语是**顶着 UID 的进程**，sudo = 让进程换 UID 跑（第 00/04 章）。
- **补"命中即停不退档"**：内核三档判定的短路逻辑，解释"我是 owner 却读不了"（第 02 章）。
- **补 umask / ACL / chattr**：新文件默认权限的来源、超越三档的精细授权、连 root 都拦的文件锁（第 02 章）。
- **补共享目录完整配方**：原版只讲到 setgid，实际还卡在 umask——补上 umask 002 / 默认 ACL 这关键一味（第 04 章）。
- **补 inode 与链接**：文件=名字+inode+数据块，硬/软链接的本质区别，解释"删文件=改目录"（第 03 章）。
- **补真实运维坑**：inode 耗尽（空间够却写不下）、`rm` 大文件空间不回收（`lsof | grep deleted`）、RAID5/6、LVM 三层与在线扩容（第 05 章）。
- **补系统账号**：UID 区间三分法、nginx 为何也是"用户"、`usermod -aG` 漏 a 的事故（第 01 章）。
- **新增排查指南**：Permission denied / 磁盘满 / 加组没生效 三棵决策树 + `namei -l` 等招牌命令 + 一页纸速查卡。

## 怎么用

- **系统学**：按 `00 → 05` 顺序读，每章结尾"✅ 自检"答得出再往下。
- **查操作**：每章有命令表与"🧠 速记卡"，是该主题可直接照抄的压缩结论。
- **修故障**：直接翻《Linux 排查指南》，照第 9 节"一页纸速查卡"跑一遍。

### 给 AI agent 的使用提示
- 每章"🧠 速记卡"= 可直接引用的压缩结论；正文 = 展开依据；排查指南的决策树是**确定性**的，可直接据此逐步定位。
- 命令均标注了**是否需要 root**与**风险**；在多用户机上操作前，先按"三个追问"定位。
- ⚠️ 写操作（chmod/chown/mkfs/fstab 等）在共享机上务必先确认无人占用、先 `df -hT` 确认盘，再执行。
